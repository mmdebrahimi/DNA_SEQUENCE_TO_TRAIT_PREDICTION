## READ THIS FIRST — do not implement picks 1 or 4 as written

The set below was generated by `/hypothesise`, which ranked **constraint enumeration as the
generator** (#1) and **symmetry-equivariance distillation** (#4) as the two to act on first. A
review the same day refuted both by reading the code. **The ranking is NOT a recommendation; the
corrections are.**

### C1 — every constraint in the layer is a CODING-sequence rule, and the GLM target is non-coding

`dna_decode/constraints/universal.py` holds exactly five rules:
`cds_length_multiple_of_three`, `no_internal_stop_codon`, `ref_base_matches_cds`,
`substitution_reachable_by_single_nt`, `start_codon_present`. Four name CDS or codons outright, and
`ref_base_matches_cds`'s own docstring calls it *"the coordinate check that catches a frame/offset
error."*

A bacterial promoter has **no reading frame, no codons, no start codon and no internal stop**, so on
the promoter substrate the admissible set those laws define is EVERYTHING. Enumerating it enumerates
all 3x150 single substitutions with nothing constrained. "Correct by construction" was read as
"constrains any edit"; it constrains **coding** edits.

**This SCOPES the hypothesis rather than killing it.** On a coding target the rules genuinely bite,
and `substitution_reachable_by_single_nt` is exactly the codon-accessibility constraint this repo's
own BLOSUM work found does most of the explanatory work. So pick #1 is viable for `forward`-cell
targets (TEM-1, CTX-M-14, HIV RT) and **vacuous for the GLM promoter target** — the opposite of how
it was pitched.

### C2 — all three symmetries named in pick #4 are wrong for this substrate

- **Reverse-complement invariance is FALSE for a promoter.** A promoter is directional: the -10 and
  -35 boxes have a defined orientation relative to the transcription start. Reverse-complementing
  describes a promoter pointing the other way, not the same one.
- **Synonymous-codon equivalence is INAPPLICABLE.** Promoters are non-coding; there are no codons.
- **Spacer-length shift is NOT an invariance** — it is a known activity determinant, which is why
  `Spacer` is one of the five element columns in `dna_decode/glm/expression.py`'s substrate.

The idea's LOGIC survives: a symmetry target is orthogonal to the feature-span argument that blocked
value-distillation, so it evades the exact objection that stopped the method. **The specific
symmetries do not, and without a valid one there is nothing to train on.**

Worse, the gap was named in the hypothesis's own design notes — *"not explored: measuring which
symmetries this substrate actually exhibits before choosing them"* — and then acted past. **Naming a
check is not performing it.**

### C3 — "generation requires a learned generative model" is a STRAWMAN; generators already ship

`dna_decode/glm/generate.py` defines a `Generator` protocol plus `HFGenerator`.
`dna_decode/glm/baselines.py` defines `UniformGenerator` ("the discriminator's POWER control") and
`MarkovGenerator`, whose docstring reads **"THE NULL a learned generator must beat."** So the
assumption pick #1 claimed to relax is not one this project holds, and any enumeration proposer has
a **named incumbent null**. Also: `constraints/` exposes `all_constraints`, `constraints_for` and
`detect_conflicts` — it VALIDATES, it does not propose. **There is no enumeration API.** Pick #1 is
a build, not a wiring job.

### Medium

- **M1** The *79% of achievable selection value at k=10* figure says the RANKER converts rho 0.59
  into most of the achievable value **on whatever candidate pool that run used**. It was used to
  argue candidates are the missing half. If that pool came from an existing generator, the figure is
  evidence those generators are ADEQUATE. Read the pool's construction before resting anything on it.
- **M2** Picks #1 and #4 were presented as independent bets. C1 and C2 are the SAME substrate
  mismatch surfacing twice, so it was one bet made twice.
- **M3** No baseline panel was specified for either pick, though the problem statement named the
  panel as a success criterion. An enumeration proposer scored against no null reproduces the exact
  defect `MarkovGenerator`'s docstring exists to prevent.

**Measure which invariances the substrate actually exhibits**, using the 10,898 pairs already on

choices. That either supplies pick #4 with a valid target or kills it with a recorded negative. No

Of the six unselected hypotheses, **#2 (bounded proposal radius)** is the one untouched by these
findings: it needs no symmetry and no constraint semantics, and rho-versus-mutational-distance has
never been plotted for any oracle here.

## The problem statement the set was generated against

> How can we train a generator that proposes genome edits for a named bacterial phenotype, when
> measured labels exist only for sequences someone already assayed and the generator will query the
> oracle off that distribution?

Grounded in the 2026-10-07 finding that the scoring half is adequate and the GENERATOR is the
bottleneck. Domain `biology`; 12 drafts, 8 emitted, 2 rejected trivial (parts-registry composition
is standard synbio; natural-variation validation is the shipped AMR comparative-genomics work), 2
rejected vague.
